# Nirmaan principles

These are the north-star rules. When a decision is unclear, they settle it.

1. **Proof over promises.** Every claim on the site is backed by something real: a system built, a demo that runs, a trade-off explained. If it can't be shown, it doesn't go on the homepage.
2. **Depth over breadth.** Two or three excellent case studies beat ten shallow projects. When in doubt, cut a project rather than add one.
3. **Clear in 60 seconds.** A hiring manager should understand what the work is, that it's real, and how to reach the owner within a minute, on a phone. Any design or feature that slows that down has to earn its place.
4. **Show how you think, not just what you used.** Lead with the problem, constraints, decisions, and what would change. The tech stack is supporting detail, never the headline.
5. **Ship small, grow deliberately.** Version 1 is a finished, focused site, not a platform. New sections (lab, products, writing) are added only when there is real content for them, never as empty placeholders.
6. **The name carries the credibility.** Nirmaan is the studio, but the person is being evaluated. "By Somnath Jha" stays visible and consistent, and nothing on the site reads as bigger than what actually exists.
7. **Built like the work it describes.** The site is itself an engineering sample: fast, accessible, cleanly structured, easy to maintain, content separate from code. It should hold up if someone inspects it.
8. **Honest and confidential.** Never overstate a role, and never expose employer or client material. If a project can't be shown as-is, abstract it or rebuild a sanitized version.

## Three questions before adding anything

1. Does it prove something real?
2. Does it help a recruiter decide faster?
3. Can it be finished and maintained?

If the answer to any one is no, it waits.
